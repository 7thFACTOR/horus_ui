Horus UI API reference

An immediate-mode graphical user interface library for C++. This page is the index of the whole public API in include/horus.h.

What is Horus UI?

Horus UI is an immediate mode GUI library: the UI is rebuilt every frame by calling widget functions, so the UI state is derived from the code that draws it. Widgets are drawn into a window docking layout, themed through per-element images, colors, fonts and states, and rendered in a batched vertex command list.

How the API is organized

Types

Handles, aliases, 2D math structs, flags enums, input, render and display info structs.

Core

Contexts, the per-frame loop (contextUpdate, frameBegin/End), input events, mouse cursors, clipboard.

Windowing & toolbars

Native windows, dock nodes, dockable windows, saving/loading dock layouts, overlay toolbars.

Themes & fonts

Creating and using themes, styles, widget/element infos, font creation and text measurement.

Layout & tables

Layout areas, id stacks, tables, scroll views, virtual lists, padding, spacing, scale and tint.

Widgets

Boxes, popups, buttons, inputs, sliders, labels, trees, menus, tabs and the rest of the widget set.

Rendering & utility

Custom widgets, render drawing primitives, drag & drop, color/vector/file dialog combined widgets, color utils.

The frame loop

A minimal frame that updates one window looks like this:

bool running = true;
while (running)
{
	hui::contextUpdate();       // process input events, animations, throttling
	hui::frameBegin();          // start a new UI frame
	hui::renderBegin();           // begin the batched rendering

	hui::windowBegin("main", "Main window");
	if (hui::button("Click me")) { // act on the press }
	hui::windowEnd();

	hui::renderEnd();
	hui::frameEnd();
	hui::present();               // present each native window backbuffer
}

Setup

The library only talks to the OS through a set of function pointers in hui::Services. You either fill Settings::services yourself or pick one of the built-in backends, then create a context: 

auto settings = hui::Settings{};
hui::initBackend(settings.services);              // from a backend, e.g. Win32/GL

HContext ctx = hui::contextCreate(settings);
hui::contextSet(ctx);

HTheme theme = hui::loadThemeFromJson("themes/default.theme.json");
if (!theme) theme = hui::createBuiltinTheme(settings.defaultAtlasSize);
hui::themeSet(theme);
hui::themeBuild(theme);

Conventions

  • All public functions are in the hui namespace, in include/horus.h.
  • Opaque handles (HTheme, HImage, HFont…) are pointers kept by the library.
  • Widgets take a const char* id or generate ids from setLabelAndId; ids keep per-widget persistent state.
  • Widget functions that can change a value return true when the change happened.
  • Most widget names have Begin/End pairs so content can be drawn between them.
  • Colors are Color floats (0..1) convertible to packed Rgba32.
  • Layout works in unscaled pixels; the global scaleSet scales rendering.
