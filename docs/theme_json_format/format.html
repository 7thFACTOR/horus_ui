Format reference

The complete JSON grammar used by hui::loadThemeFromJson(), in the order the loader processes it.

Top level

KeyTypeRequiredDescription
fonts object optional Named fonts referenced from state definitions. See fonts.
settings object optional Arbitrary string key/value settings. See settings.
widgets object required Every widget style in the theme. See widgets.

The root must be a JSON object. Unknown top-level members are ignored by the loader. If parsing fails or widgets is missing, the loader returns null (or the built-in procedural theme on a JSON syntax error) and writes the error into the optional error buffer.

fonts

Each key is a font name that state definitions can reference with the "font" field.

KeyTypeRequiredDescription
<name> object yes Any name, e.g. normal, large-bold. Referenced as "font": "normal".

A font entry object:

KeyTypeRequiredDescription
file string yes Path to a .ttf/.otf file. Relative paths (no :) are resolved against the theme file’s directory, so "fonts/Inter-Regular.ttf" loads themes/fonts/Inter-Regular.ttf. Paths containing : are used as-is.
size number yes Font face size in pixels. Entries with size 0 are skipped. 
"normal":      { "file": "fonts/Inter-Regular.ttf", "size": 12 },
"normal-bold": { "file": "fonts/Inter-Bold.ttf",   "size": 12 }

settings

An arbitrary string key/value store read at runtime with themeGetUserSetting(). Only string values are stored — non-string values are silently ignored by the loader.

KeyTypeDescription
<name> string Any setting name with a string value. 
"sameLineHeight": "22",
"dockPreviewNativeWindowsColorTint": "200 200 200 255"

The names used by the shipped themes (and their consumers) are listed on the settings page.

widgets

The widgets object maps a widget name to its definition. Widget names are case- and spelling-sensitive: see the widget name table for the recognized names.

KeyTypeDescription
<widgetName> object A recognized name describes a built-in widget; any other name is stored as a user widget whose elements are addressed by string name in code.

Styles

A widget can define several styles, for example a normal default and an emphasized important button. The active style is chosen at runtime with widgetSetStyle(). Each style is a map of element name to element description. 

"button": {
	"styles": {
		"default":    { "buttonBody": { ... } },
		"important": { "buttonBody": { ... } }
	}
}

If the widget object has no styles key, the loader uses the widget object itself as a single style named "default": 

"buttonGroup": {
	"buttonGroupLeftBody": { ... },   // elements directly under the widget == "default" style
	"buttonGroupMiddleBody": { ... }
}

Elements

Within a style, each key is an element name (see Element names). Unknown names become user elements. An element object holds element-level members plus per-state objects:

KeyTypeDescription
width, height number Element dimensions in pixels, inherited by every state that does not override them. Used for icons, carets, knobs, arrows and other fixed-size elements.
normal, focused, pressed, hovered, disabled object Per-state visual description. See states.
<paramName> string Style parameter, e.g. "indent": "10". Only string values are stored. See Parameters.
Parameters must be strings The loader only stores a parameter when its JSON value is a string. Numbers such as "count": 30 or "rowHeight": 0.0 are ignored (some shipped themes still use numbers; the reader then falls back to the code default). Write them as strings — "count": "30", "rowHeight": "0" — to take effect.

States

Each state is an object describing how the element looks in that interaction stage. The recognized state keys are normal, focused, pressed, hovered and disabled.

KeyTypeDescription
image string Base name of a PNG image without the extension, resolved against the theme directory: "default/button_normal" loads <themeDir>/default/button_normal.png. An empty string keeps the fallback __WHITEIMAGE__ (flat color fill tinted by color).
border integer 9-slice border thickness in pixels (0 = stretch the whole image).
color color string Tint/multiply color applied to the image; with the white fallback this is the fill color.
textColor color string Color of text drawn over the element.
font string Name of a font from the top-level fonts section, e.g. "normal".
width, height number Overrides the element-level dimensions for this state.
textShadow object Presence enables a text shadow. See below.

textShadow

KeyTypeRequiredDescription
color color string no Shadow color.
offsetX number no Horizontal offset in pixels.
offsetY number no Vertical offset in pixels.

Inheritance and defaults

The loader fills every element/state combination before reading JSON (all states default to the white image, white colors, no border, size 0). A JSON entry then overrides it with these rules:

  • normal is the base state. States that set a member but omit others inherit that member from normal.
  • A state key that is absent entirely copies the full normal state.
  • When an element has no normal state, all states keep the loader defaults, except that the element-level width/height still apply.
  • Missing image falls back to the white __WHITEIMAGE__, so a state can only change color.
"buttonBody": {
	"height": 22,                          // element-level default, inherited by all states
	"normal":  { "image": "default/button_normal", "border": 3,
	           "color": "120 120 120 255", "font": "normal" },
	"hovered": { "color": "155 200 200 255" },   // keeps image, border and font from "normal"
	"pressed": { "image": "default/button_pressed", "border": 3,
	           "color": "white", "font": "normal" }
}

Resolution of relative paths

All file references are relative to the directory containing the theme JSON file: "fonts/Inter-Regular.ttf" → <themeDir>/fonts/Inter-Regular.ttf, "default/button_normal" → <themeDir>/default/button_normal.png. A path containing a colon (:), such as C:/path/to.ttf, is used verbatim.
