Theme JSON format

How to describe a full Horus UI theme in a single .json file — fonts, colors, 9-slice images and per-state visuals for every widget.

What is a theme?

A theme is a set of visual descriptions for the widgets of the library. Every widget is built from one or more elements (bodies, arrows, marks, knobs, carets…), and every element can look different in each state: normal, focused, pressed, hovered and disabled. An element renders a PNG image that is scaled with a 9-slice border and tinted with a color, and text drawn over it uses a theme font and a text color.

Themes are stored as JSON and loaded with hui::loadThemeFromJson(). Three themes ship with the library: themes/default.theme.json, themes/flat.theme.json and themes/win94.theme.json. A theme directory also contains the referenced PNG images (in sibling folders like themes/default/) and fonts (in themes/fonts/).

Where the code lives The loader is backends/json_theme_loader.cpp (hui::loadThemeFromJson). Fonts, images and user settings are turned into library handles in src/horus.cpp, and the fallback procedural theme is built in src/builtin_theme.cpp.

Loading a theme

char err[2048] = {};                 // optional error buffer
HTheme theme = hui::loadThemeFromJson("themes/default.theme.json", err, 2048);

if (!theme) { // parse error: err holds the JsonCpp message
	theme = hui::createBuiltinTheme(hui::contextGetSettings().defaultAtlasSize);
}

hui::themeSet(theme);
hui::themeBuild(theme);   // pack all images into the atlas texture

The document at a glance

A theme file is an object with three optional sections. Only widgets is required.

{
  "fonts":    { "normal": { "file": "fonts/Inter-Regular.ttf", "size": 12 }, ... }
  "settings": { "sameLineHeight": "22", ... }                       ← arbitrary string key/value store
  "widgets":  { ← required
    "button": {
      // either an explicit styles map ...
      "styles": {
        "default":    { "buttonBody": { ...elements + states... } }
        "important": { "buttonBody": { ... } }
      }
      // ... or no "styles" key: the widget object itself is the "default" style
    }
  }
}

Key concepts

9-slice images

Images are 9-slice: the border value of a state defines the thickness (in pixels) of the unscaled corner and edge strips. Stretching only the middle keeps corners crisp and rounded edges intact. Draw a generous, uniform border (for example 3 to 6 pixels) and keep decorations inside it.

The fallback white image

Every theme gets a built-in white image named __WHITEIMAGE__. When a state has no image (or an empty "image" string), the element renders this white image tinted with "color" — the easiest way to produce flat colored rectangles without any PNG.

States inherit from normal

The normal state is the base. Every other state falls back to it member-by-member, so a style override can be as short as "hovered": { "color": "sky" }. If a state is missing entirely it copies normal. If an element has no normal state at all, all states use defaults (white image, white color, element-level width/height).

Colors

Color values are either a named constant or a "R G B A" string of four integers in the 0..255 range (space separated). Parsing is done by colorFromText() in src/horus.cpp.
